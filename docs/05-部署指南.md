# 用自己的 Render 專案部署家庭記帳

此指南使用**這份儲存庫 `ChunWei-0801/-` 的 `main`**，不使用原作者的服務或網域。架構是：一個 FastAPI Web Service 同源提供靜態前端與 `/api`，加一個 PostgreSQL 資料庫；模型服務可選；正式環境的信箱驗證必須配置 Brevo 與已驗證寄件人。

**目前提供部署設定與操作流程，沒有宣稱已建立或驗證公開服務。** 公開網址由你的 Render 帳號實際建立後決定，不存在預先保證可用的網址。

## 1. 部署前在本機驗證

```bash
python run.py --sqlite
```

瀏覽器使用啟動命令印出的前端網址，確認登入、記帳、統計、家庭及資料保留。正式部署使用 PostgreSQL，若具備 Docker，另執行 `python run.py` 驗證 PG。完整清單見 [04-發表與驗收手冊.md](04-發表與驗收手冊.md)。

`--sqlite` 使用本機 `backend/demo.db`，適合不需要 Docker 的展示；正式環境使用 Blueprint 建立的 PostgreSQL，不使用 Web Service 的暫存檔案保存交易。若要測試完整 Docker Compose，先在專案根目錄安裝依賴並建立本機設定：

```bash
python -m pip install -r backend/requirements.lock
cd backend
python -m app.cli init-env
cd ..
docker compose up -d --build
```

`backend/.env` 已存在時不用重新建立。Compose 的 API 建置 context 是專案根目錄，Dockerfile 是 `backend/Dockerfile`，會一併包含前端；不要在 `backend/` 內單獨建置這個 Dockerfile。完整 Compose 會開啟資料庫、API 與靜態前端，請先停止 `run.py`，避免搶用相同埠號。停止服務可用 `docker compose stop`，保留資料卷；不要使用 `down -v` 作為一般重啟。

不要把 `.env`、SQLite 展示資料、JWT、模型 key、真實家人資訊加入 commit。可以用 `git status --short` 檢查準備發布的檔案；不要用會印出所有環境變數或機密檔案的命令。

## 2. 先把審閱後的程式保存至自己的 GitHub

先確認自己的 GitHub `main` 已包含 `run.py`、`backend/`、`frontend/`、`render.yaml`。
雲端工作目錄及本機修改不會自動出現在 GitHub；新的修改需要提交並推送，Render 才能讀到。
若上述檔案已在自己的 GitHub `main`，可以直接前往第 3 節建立 Render Blueprint。
以下為從下載包建立自己的儲存庫，或保存後續修改的指令。
如果是從 ZIP 解壓到新資料夾、尚未有 .git，先在該資料夾初始化；已有本環境checkout就略過，不更改既有origin：

```bash
git init
git remote add origin https://github.com/ChunWei-0801/-.git
```

先用 `git status --short` 確認不包含 .env、資料庫或真實個資，再於專案根目錄執行：

```bash
git add .gitignore .dockerignore README.md SOURCE.md backend frontend docs run.py docker-compose.yml render.yaml
git commit -m "完善家庭記帳專題與發表文件"
git branch -M main
git push -u origin main
```

這些是你確認後的發布步驟；沒有執行之前，不能宣稱 GitHub 或 Render 已更新。

## 3. Render New Blueprint

1. 登入自己的 Render 帳號，連接能讀取 `ChunWei-0801/-` 的 GitHub 帳號。
2. 選 **New → Blueprint**，選儲存庫 **`ChunWei-0801/-`** 與分支 **`main`**。
3. Render 讀取根目錄 `render.yaml`。檢查列出的 Web Service 與 PostgreSQL；名稱以此檔與你實際建立的資源為準，不必與原作者相同。
4. 查看服務方案、資料庫容量、有效期限和價格。Render 可用方案依帳號與當時平台規則而定；文件不保證任何方案免費或永久保留資料。
5. 使用下節方法填入安全設定。確認 Blueprint 指向自己的儲存庫及預期資源，再套用。
6. 等待安裝、資料庫遷移與啟動；失敗時先看 Build／Runtime logs，再依錯誤排除。日誌若含機密，不要貼出完整內容。

單服務部署由 FastAPI 供應 `frontend/` 靜態檔案，資料請求走同一服務的 `/api/...`。不是「只把 frontend 拖上去」的部署：只有靜態頁面不能保存真後端交易。

## 4. 環境變數與機密

| 名稱 | 設定方式 | 用途 |
|---|---|---|
| `REQUIRE_EMAIL_VERIFICATION` | Blueprint設為`true` | 正式註冊不發登入權杖，先完成信箱驗證 |
| `APP_ENV` | Blueprint設為`production` | 正式錯誤處理與安全模式，不播種固定開發帳號 |
| `DATABASE_URL` | `fromDatabase`連到本Blueprint的PostgreSQL `connectionString` | 使用平台注入的資料庫綁定，不手抄密碼到Git |
| `JWT_SECRET` | 此Blueprint已設定`generateValue: true`，由Render自動產生 | 簽發JWT；保留平台產生的值，不必另外產生或複製 |
| `APP_BASE_URL` | 建立後，填自己的`https://...onrender.com`或自訂網域 | 密碼重設連結等公開前端地址 |
| `ALLOWED_ORIGINS` | 同源Blueprint預設空白；另部署前端才填該前端的完整origin，多個用逗號分隔 | 允許瀏覽器來源；不要填原作者網域或用`*`代替排錯 |
| `MODEL_BASE_URL` | 有模型服務才在安全環境設定；可先留空 | LLM推論服務base URL |
| `MODEL_NAME` | 與實際服務接受的模型名一致 | 版本紀錄及服務選擇 |
| `MODEL_API_KEY` | 服務要求驗證時才填Secret | 模型授權；公開無驗證服務可留空 |
| `BREVO_API_KEY` | 正式信箱驗證與忘記密碼寄信必須填Secret | Brevo HTTP API key |
| `MAIL_FROM`／`MAIL_FROM_NAME` | 填已在Brevo驗證的寄件地址／顯示名稱 | 郵件寄件人 |
| `ADMIN_EMAILS` | 若需要，填自己註冊並管理的帳號 | 配合支援的make-admin流程；不等於可讀家庭財務 |

`APP_BASE_URL`、`MODEL_API_KEY`、`BREVO_API_KEY`、`MAIL_FROM` 使用`sync: false`，由你在Render安全欄位設定，不把值加入Git。模型與寄信相關欄位是選用功能：沒有設定時，核心記帳仍可使用，介面會標示規則備援與寄信服務未設定；只有要啟用對應功能時才填。密鑰不貼在聊天、issue或簡報；JWT密鑰輪替會使舊權杖失效，要安排重新登入。

不要手改平台注入的 `DATABASE_URL`。程式會將Render常見的`postgres://`／`postgresql://`連線格式正規化為psycopg驅動，保留原本的連線參數與SSL設定。如果仍有連線錯誤，核對資料庫狀態與實際安裝的驅動，不公開連線字串。`DATABASE_URL`的名稱可以報告，值不應報告。

## 5. 得到自己的網址之後

1. 從 Web Service 的 Dashboard 複製**自己服務**的公開 URL。
2. 設定 `APP_BASE_URL` 為此URL；若需要 `ALLOWED_ORIGINS`，也填此實際來源。自訂網域要等DNS與TLS正常後再填對應來源。
3. 存檔並重新部署／重新啟動，讓環境設定生效。
4. 在一般與無痕視窗打開此公開URL。確認Network中資料請求送到**同一服務的 `/api`**，而不是 `localhost` 或原作者網站。
5. API互動說明書在同一URL的 `/docs`，產品學習手冊在 `/docs/index.html`；`/docs/`可能轉回Swagger，請使用完整HTML路徑。發表頁、操作教學與中英名詞分別在 `/docs/presentation.html`、`/docs/guide.html`、`/docs/glossary.html`。
6. `/healthz`確認服務可回應；`/readyz`會實際查詢資料庫，正常時回傳`{"status":"ready","database":"ok"}`。Blueprint使用`/readyz`作為健康檢查。`/capabilities`會回報模型與寄信是否設定，不提供密鑰。

前端走 `#/entry` 等hash路由。井號後面不傳給伺服器；不要另外加入「任何路徑都回index.html」的通配rewrite去遮住 `/api`、`/docs` 或真正靜態文件。

## 6. 公開環境驗收

- [ ] 明確看到真API模式，確認不是mock或指向原作者網域。
- [ ] 手動記帳成功，重新整理與另一個瀏覽器能讀到。
- [ ] 段落解析的模式與備援如實顯示；確認寫入後端並保存。
- [ ] 收支統計可由明細驗算；家庭A/B的角色與反向權限符合契約。
- [ ] Web Service重新啟動後，PostgreSQL資料仍保留。
- [ ] 正式信箱驗證已收信並完成；若測忘記密碼，實际收到並使用重設連結，連結指向自己的URL。

## 7. 常見部署問題

| 現象 | 排查順序 |
|---|---|
| Build失敗 | 核對Python版本、requirements、render.yaml路徑；讀第一個具體安裝錯誤，不以停用TLS驗證解決 |
| 資料庫連不上 | 核對同Blueprint資料庫是否可用、fromDatabase綁定與SQLAlchemy驅動；只看變數存在與狀態，不公開值 |
| Migration失敗 | 讀Alembic具體revision與資料約束錯誤；保留資料，不要為了上線直接刪資料庫 |
| 首頁404或資產404 | 核對FastAPI靜態路徑是否包含frontend及文件；不要用rewrite遮住API |
| 請求還打localhost | 檢查前端API設定與舊瀏覽器快取／localStorage；公開頁應使用自己的同源API |
| CORS錯誤 | 核對協定、主機與埠號完全相同的origin；不要把任意網域加入允許清單 |
| 模型503 | 檢查模型服務可用性、base URL、服務接受的MODEL_NAME與驗證；規則模式可用但不是模型驗收 |
| 忘記密碼失敗 | 核對Brevo HTTP API、驗證寄件人、APP_BASE_URL；沒有服務設定就明列未配置 |
| 資料庫方案到期／容量限制 | 查看自己帳號的方案與平台通知，先備份並驗證可還原，再規劃遷移或升級 |

正式資料需要自己的備份與還原策略。不要因服務提供PostgreSQL就宣稱已有可還原備份，實際還原驗證才是證據。

## 7. 更新、重啟與備份

1. 更新程式前，先備份PostgreSQL。若方案提供平台備份，查看實際保留期限與還原方式；沒有此功能時，在自己的終端機使用PostgreSQL工具匯出。將連線設定放在本機安全環境變數，以下命令不包含密碼：

   ```bash
   pg_dump --format=custom --no-owner --file=fambudget-backup.dump "$FAMBUDGET_DATABASE_URL"
   ```

2. 備份包含帳號與收支資訊，存放在私人位置，不提交Git。另建一個空的測試資料庫，將它的連線設定放入`FAMBUDGET_RESTORE_DATABASE_URL`，再驗證還原；此變數必須指向測試資料庫：

   ```bash
   pg_restore --no-owner --dbname="$FAMBUDGET_RESTORE_DATABASE_URL" fambudget-backup.dump
   ```

3. 確認還原後的帳號與交易筆數、金額及家庭關係。記下備份日期、版本與驗證結果；只產生備份檔不等於已驗證可還原。
4. 將已審閱的程式碼提交到自己的`ChunWei-0801/-`，由Render的自動部署或Manual Deploy更新。啟動命令依序套用資料庫遷移、建立系統分類，再啟動服務；正式環境不建立固定密碼的開發帳號。
5. 重啟後先檢查`/readyz`，再登入原帳號確認資料保留，至少重做一筆記帳、統計驗算及權限反向測試。更新環境變數也需要重新啟動，請以執行結果確認新設定已生效。

## 8. 雲端開發環境與公開網站的差別

Codex的雲端環境設定保存安裝與啟動指令，讓後續任務可以重現開發流程；保存設定不會自動提交GitHub、建立Render服務或公開網站。Render Blueprint才是用你自己的帳號建立可對外連線的應用與資料庫。請將「本機／雲端開發已驗證」與「公開網址部署後已驗證」分開記錄；只有第5節實際完成的項目才能寫入公開部署的驗收紀錄。
