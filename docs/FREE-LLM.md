# 免費裝置端 LLM 與試用驗收

## 可測試入口與費用範圍

- `/ai-test.html`：不需帳號的真實模型試跑頁。明確啟動後載入模型，可輸入文字或執行兩筆合成範例欄位比對；不寄信、不讀寫帳務。
- `/#/ai`：登入後的完整 AI 試用頁；總覽常用功能與設定均有入口。功能仍採明確啟動及確認寫入，供使用者先測試再決定是否持續使用。
- 模型推論在使用者裝置執行，沒有付費 API、API 金鑰、雲端推論帳單或自動付費備援。初次模型下載約 290 MB，仍使用使用者自己的網路流量、電力與裝置資源。
- 需要安全來源 HTTPS（本機 localhost 例外）、WebGPU 及約 1 GB 可用 GPU 記憶體。沒有通過裝置檢查時明確拒絕載入；手動記帳與既有報表保留。不保證所有手機都能運行模型。
- WebLLM 可能快取模型檔；離開 AI 頁、登出或切換帳號／家庭權限上下文時清除本次輸入、查詢資料及模型工作階段，不將對話或帳務快照寫入瀏覽器儲存空間。明確確認入帳的原始輸入會和解析紀錄一起保存至帳號資料庫，畫面在確認前提示。

## 模型與資料流程

使用 [WebLLM 0.2.86](https://webllm.mlc.ai/docs/user/get_started.html)，在同來源的 module worker 內執行開源 `Qwen2.5-0.5B-Instruct-q4f16_1-MLC`。若 GPU 沒有 shader-f16，改用同一個小型模型的 q4f32 版本；兩者都需要 WebGPU。約 945／1060 MB 是官方模型登記的 GPU 記憶體估計，不是各裝置實測結果。模型來源與編譯資源由官方 WebLLM 登記提供，第一次下載需要外部資源連線。

文字記帳：使用者文字 → 真正 LLM 引用原文片段、金額原文並選可讀的收支／分類合併標籤及日期詞 → 原文對齊、金額格式驗證、唯一分類查表與已提供的日曆日期對照 → 標準記帳草稿 → 可編輯欄位 → 明確選擇帳本與確認 → 既有後端驗證及交易。程式不以規則產生新的交易或金額；版本 171 另加入明確揭露的來源規則協助，核對可省略欄位與明確收支／分類線索。模型原判斷、規則調整及最後可編輯草稿分開保留；未涵蓋或歧義情況仍需人工核對。多筆使用既有批次確認接口，全部通過才一次寫入。模型沒有資料庫寫入權限。

照片記帳：相機／照片 → Tesseract.js 7 本機 OCR → 可修改辨識文字 → 同一文字模型產生草稿。這是 OCR 加文字 LLM 的兩階段流程，沒有將文字模型宣稱為視覺語言模型。圖片只有在使用者確認附加後才透過既有私有照片接口保存；上傳失敗不再重複新增記帳。

帳務問答／儲蓄教練／月報：使用者明確選擇月份與個人／家庭範圍 → 受權限控制的唯讀工具 → 後端 Decimal 精確統計及具識別碼的來源 → 模型解釋 → 來源與精確事實分開展示。這是受控查詢工具輔助生成，沒有宣稱小型 Qwen 支援原生 function calling。模型不能自選使用者、執行 SQL 或擴張家庭權限；僅有摘要權限的監管關係不提供單筆交易內容。

操作問答：固定的本機雙語教學／規則語料 → BM25 檢索相關段落 → 附來源的模型回答。這是檢索增強生成（RAG），不需要額外付費向量資料庫；未經測試不宣稱微調或嵌入模型。對話問題留在裝置，檢索接口只接收操作主題查詢。語料目前為繁中／英文，其他介面語言由本機模型產生回覆。

## 正確性與測量

- 金額、差額、分類總額與儲蓄缺口由伺服器計算，回傳精確十進位字串；交易分頁不得冒充完整總額。
- 帳務與教學來源以識別碼引用；輸入、收據、名稱與段落均當作資料處理。回覆若引用不存在的來源、引入證據沒有的數值、截斷或空白，須顯示錯誤，不呈現為成功回答。
- 引用與數值檢查只是防護，不等同於證明所有語意正確。使用者仍須核對來源；小型模型可能誤解分類、時間或敘述。
- 試用頁記錄實際模型名稱、延遲、輸入／輸出 token（runtime 有提供時）、來源數及使用者核對結果；下載的評估紀錄不包含原始輸入、照片、帳務或回答。
- 公開測試頁的兩筆合成範例只有在實際生成後才顯示欄位比對結果；不能把兩筆結果外推為整體模型準確率。

## 驗收證據的區分

目前上線來源為 `81abbe15a50f6d60fc5550acf581b45d18396467`，資源版本 171。Render 部署 `dep-dbc9sp3bc2fs73bp4ia0` 於 2026-10-21 19:15:20（臺灣時間）回報 live；仍使用既有免費服務與同一個模型。公開試用連結為 `/ai-test.html?v=171`，登入後為 `/#/ai`。不需新增金鑰、清除權重快取或下載更大模型。

使用者真正失敗原文已取得：模型引用早餐 65 與午餐 120，卻把午餐判成薪資並捏造「收銀員3號」；選填商家引用不符導致兩次推論後整份拒絕。版本 171 清空無來源選填值，並明確顯示有限的來源規則協助。規則只核對已對齊的模型列，不產生新交易或金額；分類按當次真實名稱唯一匹配，不認任意 ID 或案例正解。否定、預算、退款及不明第三方付款保守留待人工判斷；沒有詞彙覆蓋時保留模型選擇並提醒核對。

公開頁把模型原判斷與來源檢查後草稿分開比對，不把規則結果算成純模型準確率。登入後每列顯示可讀提醒，實際調整才保存為 `hybrid`，純核對提醒仍為 `model`；明確確認後的稽核原值保留模型原判斷。原始模型回覆、調整明細只留本頁記憶體；評估匯出只含非內容的布林與計數，不含原文或原分類／商家值。

目前有 66 項前端相關檢查通過且零跳過（worker 44、登入頁 11、公開頁 4、API 6、整合重播 1）、888 項後端測試通過，GitHub run [39590123146](https://github.com/ChunWei-0801/-/actions/runs/39590123146) 的 checks 與真正 Chromium browser job 均成功。整合重播使用原始失敗輸出穿過真正 worker、controller、HTML parser、語系及 UI，驗證兩筆餐飲支出、商家留白、僅一次處理、320px 畫面及無帳務寫入。重播僅替換生成回覆與 GPU 支援探測，不能當成新的 Qwen 推論或品質驗收。範例二的薪資回覆亦明確標示為額外合成替身。獨立審查的 10 組原始欄位測試也不是模型品質測量。

模型 schema、prompt 及 model ID 未改。既有 19 項官方 web-xgrammar 0.1.27 實際 WASM 檢查仍適用；使用合成 tokenizer，只證明語法可編譯／約束。先前套件匯入、實際 OCR 與使用者裝置上的真正生成有各自證據，不能互相替代。新一輪使用者裝置真正推論仍待驗收，不預填成功率；歷次修復及失敗證據保留於 `WORKLOG-20261020.md`、`WORKLOG-20261021.md`。

目前 managed cloud 沒有可用 WebGPU，執行中政策 revision 840 仍缺模型權重、正式網站與資料庫目的地。沒有繞過限制或宣稱在此完成新推論。正式網站帳號／信箱連結／照片／手機／八項功能完整線上驗收，以及正式 PostgreSQL 私有備份隔離還原，仍依 `PRODUCTION-ACCEPTANCE.md` 分別處理；歷史／QA 異地還原不能代替正式資料持續備份。

## 課程展示建議

使用未出現在提示範例的測試集評估日期、金額、幣別、分類及多筆切分；比較有／無檢索來源的回答支持率，記錄幻覺與拒答；展示跨家庭越權被後端拒絕，以及使用者修正草稿後才入帳。另提供真實裝置的模型載入時間、生成時間和記憶體需求觀測。這些證據可以說明免費開源模型的能力、成本及限制。

版本 171 實機新證據：來源檢查後早餐 65／午餐 120 已正確，但第二薪資範例因模型額外捏造一列而整份拒絕。版本 172 改為逐筆嚴格驗證及候選隔離，有效來源／金額保留，排除列清楚提示，全部不合格仍失敗。模型原始候選數量完整保留以供獨立比對，最後草稿透過 rowMappings 連回正確的原始模型列；候選過濾後確認記帳標為 hybrid。這次實際失敗輸出重播通過，70 項相關測試通過且零跳過；仍不代表已在雲端完成新的模型推論。上線狀態以最新工作紀錄為準。
