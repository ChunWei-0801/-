## 模型與資料流程

使用 [WebLLM 0.2.86](https://webllm.mlc.ai/docs/user/get_started.html)，在同來源的 module worker 內執行開源 `Qwen2.5-0.5B-Instruct-q4f16_1-MLC`。若 GPU 沒有 shader-f16，改用同一個小型模型的 q4f32 版本；兩者都需要 WebGPU。約 945／1060 MB 是官方模型登記的 GPU 記憶體估計，不是各裝置實測結果。模型來源與編譯資源由官方 WebLLM 登記提供，第一次下載需要外部資源連線。

文字記帳：使用者文字 → 真正 LLM 引用原文片段、金額原文並選可讀的收支／分類合併標籤及日期詞 → 原文對齊、金額格式驗證、唯一分類查表與已提供的日曆日期對照 → 標準記帳草稿 → 可編輯欄位 → 明確選擇帳本與確認 → 既有後端驗證及交易。程式不以規則產生新的交易或金額；版本 171 另加入明確揭露的來源規則協助，核對可省略欄位與明確收支／分類線索。模型原判斷、規則調整及最後可編輯草稿分開保留；未涵蓋或歧義情況仍需人工核對。多筆使用既有批次確認接口，全部通過才一次寫入。模型沒有資料庫寫入權限。

照片記帳：相機／照片 → Tesseract.js 7 本機 OCR → 可修改辨識文字 → 同一文字模型產生草稿。這是 OCR 加文字 LLM 的兩階段流程，沒有將文字模型宣稱為視覺語言模型。圖片只有在使用者確認附加後才透過既有私有照片接口保存；上傳失敗不再重複新增記帳。

帳務問答／儲蓄教練／月報：使用者明確選擇月份與個人／家庭範圍 → 受權限控制的唯讀工具 → 後端 Decimal 精確統計及具識別碼的來源 → 模型解釋 → 來源與精確事實分開展示。這是受控查詢工具輔助生成，沒有宣稱小型 Qwen 支援原生 function calling。模型不能自選使用者、執行 SQL 或擴張家庭權限；僅有摘要權限的監管關係不提供單筆交易內容。

操作問答：固定的本機雙語教學／規則語料 → BM25 檢索相關段落 → 附來源的模型回答。這是檢索增強生成（RAG），不需要額外付費向量資料庫；未經測試不宣稱微調或嵌入模型。對話問題留在裝置，檢索接口只接收操作主題查詢。語料目前為繁中／英文，其他介面語言由本機模型產生回覆。

## 正確性與測量

- 金額、差額、分類總額與儲蓄缺口由伺服器計算，回傳精確十進位字串；交易分頁不得冒充完整總額。
- 帳務與教學來源以識別碼引用；輸入、收據、名稱與段落均當作資料處理。回覆若引用不存在的來源、引入證據沒有的數值、截斷或空白，須顯示錯誤，不呈現為成功回答。
- 引用與數值檢查只是防護，不等同於證明所有語意正確。使用者仍須核對來源；小型模型可能誤解分類、時間或敘述。
- 試用頁記錄實際模型名稱、延遲、輸入／輸出 token（runtime 有提供時）、來源數及使用者核對結果；下載的評估紀錄不包含原始輸入、照片、帳務或回答。
- 公開測試頁的兩筆合成範例只有在實際生成後才顯示欄位比對結果；不能把兩筆結果外推為整體模型準確率。

## v175：準確性與速度優化（實機提升幅度待測）
