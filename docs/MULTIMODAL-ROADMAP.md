# 圖片記帳研究室與多模態延伸

本文件記錄 v187 的實作界線。入口為 `/receipt-lab.html`，不需要登入，也不載入正式 API 適配器。

## 本次可以實際操作的流程

1. 選擇 JPG、PNG、WebP 或使用手機相機，圖檔最大 12 MB。
2. 明確按下辨識按鈕，使用既有 Tesseract.js 7 與繁體中文、英文語言檔在本機 OCR。首次會下載辨識資源；原圖及辨識文字不由本頁上傳。
3. 顯示可編輯原文，以正式記帳共用的 `ReceiptEntry.analyze()` 規則提出日期、店家、幣別與總額候選。多個日期或同等總額候選保留待確認，不自動填入今天或猜測總額。
4. 從簡單「名稱＋行尾金額」提出至多 30 個品項／折扣候選。無法可靠判斷數量、單價或複雜版面時，不自行補齊。可手動新增、修改與移除品項。
5. 以整數分計算目前列出品項的合計，與收據總額比較。品項可能未列完整，因此差額不是 OCR 一定錯誤的證明；使用者須核對，差額存在時另外確認以收據總額為準。
6. 使用者核對並勾選後產生、下載 JSON 草稿。JSON 不包含原圖、base64 或辨識全文；不會新增正式記帳。任何欄位或來源文字變更會使先前確認失效。

示範文字採自行編寫的虛構收據，明確標示「未執行圖片 OCR，非真實 OCR 推論」。本頁不提供 OCR 字元信心值，不將欄位完整率當成辨識正確率。

## 與視覺語言模型的差異

目前流程是圖片 → OCR 文字 → 來源規則 → 人工核對，沒有視覺 LLM、沒有模型觀看圖片，也沒有開放式視覺推理。本次不能宣稱已完成多模態 LLM 整合。

可供下一階段研究的方向：

- 評估有合適授權的開源視覺語言模型，測試圖片版面、文字與使用者問題的聯合理解。
- 比較只有 OCR 與 OCR 加視覺模型時，品項、折扣、付款方式及總額的辨識結果。
- 對低清晰度、旋轉、裁切、不同店家版面及電子支付截圖分組測試；未知欄位維持空白。
- 延續現有人工確認與後端權限檢查，模型不持有銀行操作或直接寫帳權限。
- 分別量測首次下載、啟動與已載入後推論，確認裝置記憶體、瀏覽器支援及免費服務限制。不可承諾手機可永久免費執行所有模型。

語音不是本次的必要條件。多模態研究可以先專注於圖片與文字。

## 課程展示與評估

可準備已取得同意或自行製作、不含私人資訊的固定收據集，分別保存原始 OCR、規則草稿、人工標準答案。建議欄位包括日期、店家、幣別、總額、品項、折扣；記錄每欄正確率、漏列及誤列品項、差額與耗時。對實際照片與示範文字分開統計。

瀏覽器自動化測試只驗證來源標示、檔案限制、取消及晚到結果保護、欄位核對與下載行為。測試使用標示清楚的 OCR 傳輸 fixture，不代表真實 OCR 辨識準確率。實體手機相機、真實收據及未來視覺模型效果，仍需實測。
