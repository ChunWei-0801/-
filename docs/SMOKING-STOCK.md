# 買菸與實抽包數檢查

原本兩個欄位只各自檢查非負整數，因此可以記成只買1包卻已抽2包。新版改以本人歷次紀錄依日期計算庫存，並由伺服器再次檢查；不能只靠畫面按鈕。

- 沒有剩餘包數，不能增加實抽。
- 已被實抽使用的購買包數，不能直接減掉；減少舊購買也不能造成後續日期不足。
- 上月結餘會帶到下個月。例如上月剩2包、本月買0包，本月抽1包後還剩1包，屬於合理紀錄。
- 後來購買不能回頭掩蓋更早日期已經超抽的情況。系統依日期檢查，不是只看今天的總差額。

畫面新增「月初結餘」與「剩餘包數」。既有異常不會被刪除或偷偷改成0；會顯示不足包數與第一個不足日期。在「每日紀錄」找到該日按「修正」，依實際購買、實抽情況修改。舊異常可以逐步改善，但不能再加重任何日期的不足。

目前紀錄單位維持整包，同一天購買與實抽採當日總數；沒有時分秒的順序，也未新增借菸／贈菸或期初庫存類別。歷史紀錄依原本登記的曆日顯示，切換時區不會顯示成前一天。每月上限仍為使用者設定的觀察目標，不會把超過目標自動刪掉。

如果儲存結果不明，而且重新核對也失敗，會暫停包數修改，按「重新讀取」成功後才恢復。成功回應同時回傳該月權威紀錄、總計與庫存，維持單次請求並同步其他裝置的變更。成功修改會保留肺部原本的呼吸動畫節點；失敗操作不會顯示咳嗽或假成功。

程式測試包含跨月／跨年結餘、減少舊購買、歷史異常逐步修復、帳號隔離與網路失敗；隔離PostgreSQL18亦驗證了同時抽最後1包、以及減少購買與增加實抽競爭時，只允許一筆成功。自動化裝置設定不代表實體手機驗收。
