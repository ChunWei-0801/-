01 · Family finance, in everyday language
家庭記帳

把生活中的一句話，
變成看得懂的家計。

段落記帳 × 月年控管 × 有界線的家庭監管

實機展示 5–8 分鐘瀏覽器 → API → 資料庫規則模式與 LLM 模式分開說明

開場：「我們想降低每天記帳的輸入成本，也讓家庭成員在清楚的權限界線內看懂收支。接下來以真實後端示範；如果沒有模型設定，會明說使用規則解析。」

02 · The problem

記帳難在每天都願意記。

輸入成本

選分類、填金額、挑日期，零碎步驟累積成負擔。

語言有歧義

「全家」可能是店家；「給我」可能是收入；少了金額不能靠猜。

共享有界線

家長想掌握狀況，孩子也需要自己的帳與紀錄完整性。

「今天早餐55，在全家買咖啡，打工賺了1500。」

示例文字。咖啡沒有金額，應請使用者補上。

問題頁約30秒。指出規則也能處理一部分語言；模型能否改善難例，需要評測證據，不能直接宣稱不可替代。

03 · The solution

先整理，再確認，最後才入帳。

用月／年看進度

收支、分類、預算與存款目標，讓數字有下一步。

用角色與監管定範圍

家庭角色決定可用功能，監管關係決定可看對象。

約30秒。強調人可以編輯結果，批次送出才走確認 API；沒有模型也能保留手動流程。

04 · Architecture

介面、權限、資料，各有責任。

前端提供操作與顯示；後端重新檢查身分、資料範圍與寫入條件。LLM 不加總錢，也不直接改資料庫。

約40秒。SQLite用於不需Docker的展示，正式資料庫用PostgreSQL。部署設定是可用流程，不代表已經發布線上服務。

05 · Live demo

四個畫面，走完一次記帳。

① 登入與家庭

使用 A 帳號建立家庭，B 帳號加入；確認兩個身分分開。

② 段落與修正

早餐55、咖啡缺金額、收入1500。補咖啡65，確認寫入。

③ 明細與統計

從空帳開始，支出120、收入1500、結餘1380。重新整理再看。

④ 預算與權限

設定餐飲預算100，展示120的超支；用B帳號驗證全家資料被擋。

這些數字是示例資料的預期加總，不是模型準確率。展示前請依驗收手冊實際跑一次。

實機約2分30秒。開啟「系統」連結；A一般視窗、B無痕視窗。貼句子、說明模式標示、補缺金額、送出、重新整理。不要在台上清空資料庫。

06 · Access boundaries

看得到，不等於能代改。

身分／關係展示重點驗證方式
自己的帳可以記、改、刪自己的交易個人明細與確認寫入
家庭家長依家庭規則看全家統計scope=family
家庭子女不能直接取得全家總覽UI 與 API 反向測試
監管者查看獲授權對象，保留唯讀界線讀取通過，代改被拒絕

沒有登入他人帳號的功能；平台管理員身分不等於家庭財務閱讀權限。

約40秒。展示不只看按鈕是否隱藏，也要實際驗證後端拒絕未授權請求。不要把平台管理員稱為可以看所有家庭財務資料的超級使用者。

07 · Rules versus LLM

兩種解析，要明確標示。

規則模式 · Rules

本機關鍵字、金額與日期處理。模型未設定或不可用時接手；確認寫入仍呼叫真實後端。

優點：不依賴模型服務。限制：複雜語意與切分可能失敗。

模型模式 · LLM

設定模型服務後，後端請模型抽取欄位，再檢查格式；使用者仍須確認。

需要：可用端點、模型版本與真正的比較評測。

目前不宣稱已完成微調。 Qwen、LoRA／QLoRA 是訓練規劃；這次沒有產出或驗證訓練權重，也沒有可報告的模型分數。

約45秒。「今天若顯示規則備援，請把它看作產品穩定性展示，不是模型成果。訓練計畫與實測成果分開報告。」模型沒設定時路由503，只有解析備援，資料寫入不退回假後端。

08 · Honest evaluation

比較同一批題目，才知道有沒有進步。

人工留出集

先定標註規則，切開訓練／驗證／測試。留出集不拿來調 prompt，也不送進訓練。

公平對照

規則、zero-shot、few-shot、微調使用同一分類表、日期基準及後處理。

量什麼回答什麼目前狀態
整段全欄位正確率一次輸入是否完全不用修正未執行正式留出集評測
分類 Macro-F1／缺值亂猜率小分類與不知道時是否可靠未測，不能填估計值
延遲 p50／p95一般與較慢情況需要等多久須在指定模型服務實測

約40秒。API測試通過只證明程式行为，不能換算成模型準確率。保留原始預測、答案、模型版本、樣本數與執行時間，將「未測」留白。

09 · Validation

用可重跑的檢查支持展示。

功能

登入、記帳、統計、家庭、預算與重新整理後的資料保留。

邊界

缺金額、非法金額、空輸入、批次失敗回滾。

權限

未登入、別人的交易、子女全家查詢、跨家庭存取。

實際命令、測試結果與未測項目記在 docs/04-發表與驗收手冊.md。本頁列的是驗收方法，不用沒有跑過的「全部通過」口號。

約25秒。由主代理填入實際驗收紀錄；若現場需要證據，展示真實測試報告，清楚說明資料庫與模型模式。

10 · Verified email and personal backgrounds

信箱驗證，配上自己的登入畫面。

信箱驗證 · Email verification

申請 → 30分鐘單次連結 → 驗證成功 → 登入。正式環境未驗證不發權杖；開發展示清楚標示未寄信。

自由背景 · Login background

紙上晨光、森林微風、星空暮色、自己的照片。相簿與拍照、填滿／全圖／鋪排／原尺寸，位置、亮度、模糊與遮罩。

不設應用檔案大小門檻，原圖存在此瀏覽器IndexedDB。實際容量受裝置與瀏覽器限制；已驗證8.8MB照片原檔保存、重新整理及手機調整。

約35秒。切換預設和照片，說明此裝置保存。再展示驗證狀態。真正寄信須配置自己的Brevo金鑰、驗證寄件人與公開網址，不能把開發連結說成已寄信。

11 · Manual entry and currency conversion

國際匯率輔助，實際金額由人決定。

目前帳本本位幣是新臺幣，海外交易轉為TWD後統計。備註保存原幣、匯率與日期；每日參考行情不是銀行即時成交價，手續費與差價以實扣金額為準。

約40秒。選來源USD與目標TWD、看資料日期、換算、帶入手動金額後修改，再展示明細與統計。可直接手動輸入而不經過AI或匯率。
